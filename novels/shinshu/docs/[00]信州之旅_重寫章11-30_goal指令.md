## 五、章 1–7 破折號處理細則

規則係「不用連續破折號連接句子」。章 1–7 違反。
處理原則：
- 讀落去自然，唔好機械式改成「，」
- 推薦做法：拆成兩句，用「可是／但是／不過／然而」連接
- 例：`他沒有手抖。他點點頭。`（原：`他沒有手抖——他點點頭。`）
- 例子：`牠整個跳起來，前腳搭在凜的大腿上。`（原：`然後——牠整個跳起來`）
- **唔准**用逗號代替（逗號已經用咗太多）

## 十一、Token 與續航策略

- 每次只派一章（唔好一次派多章），因為上文污染會令 subagent 亂寫。
- 寫作代理嘅 context 只包含「該章大綱 + 前章收尾 300 字 + 硬設定摘要」。
- 審核代理嘅 context 只包含「該章正文 + 該章大綱 + 審核標準」。
- **每章結束後本 tick 立即結束**，由定時任務叫醒繼續。
- 若 API 覆空 / token 用盡 / "Operation interrupted"：唔好重試同一個長任務，改用下一個 tick。
- 若 subagent 死於 timeout：查 `~/.hermes/state.db` sessions 表 + `scripts/recover-subagent-report.py` 搵回報告（呢個係已知問題，見 memory）。

## 十二、Push 規則

- **每章 PASS 即刻 push**（主人指定）。
- Commit message 格式：`✨ feat(shinshu): 重寫章 XX（<標題>）`

- Push 後更新進度檔。

## 十三、已知陷阱（唔好再踩）

| 陷阱 | 說明 |
|---|---|
| **HTML 結構** | 唔好自行加 `<style>` 或 `<script>` 標籤；樣式要併入原有 `<style>` 內。已犯過一次：CSS 未包 `<style>` 導致 45 章頁面頂部出現 CSS 原始碼 |
| **注入 HTML 必驗** | 每次注入 HTML 後，用 `html.parser` 解析確認 body 可見文字無片段外露（grep「片段存在」唔夠——存在≠無外露） |
| **切勿自行刪改後段章節** | 章 39–50 已定稿審核通過，唔准因為風格問題郁佢哋 |
| **字數計法** | 用「漢字＋假名＋英數」，唔包含標點。舊稿用 ASCII 逗號，令實際中文字符數被高估/低估 |
| **舊規格已作廢** | 章 11–30 嘅 3000–4000 字規格已被新規格 1800–2800 取代 |
| **簡體字容忍度** | 主人講「少少簡體可以略過」——即係唔好主動用，但唔好因為一個兩個就整章打回 |
| **CapCut / clone 警告** | 唔好用 `git checkout` 還原已 push 嘅章節改動（會丟失進度） |
